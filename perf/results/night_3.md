# 第3项：5秒连击数字与药丸推挤修复

1. **改了什么**：礼物聚合改为同 uid/用户名+礼物名的5秒滑动窗口，删除布局层 combo_id/combo_mode 分支；保留 tid 去重，数量和金额逐条求和。合并礼物拆为状态事件，数字按 ×1、×2…递增，事件严格首尾相接，宽度固定；修复状态路径冻结覆盖后续礼物 reflow 的问题，并把扫描线改为半开区间避免边界重叠。
2. **为什么这样改**：用户反馈后续礼物到达时已有药丸没有被推上去；根因是 `_freeze_gift_state_paths` 把 `_layout_stacked_panels` 计算出的上移路径重置回初始 Y。现在只固定状态切换的 X/进入退出行为，保留每个状态自己的堆叠 Y 位移。
3. **遇到的问题和解决办法**：交错素材中还发现聚合函数在已有分组上复用了上一个新分组的临时变量，导致×1到×8被截断；已改为显式使用 `previous`。真实裁剪 GPU 演示验证了×1到×8、宽度220px不变，以及后续礼物到达后已有药丸从Y=1813上移到更高位置。
4. **意见和想法**：E/G 共用连续 RenderPlan 事件，不需要修改 GPU 合成器；`EventScanner` 使用半开区间后，状态边界不会同时激活两张药丸。
5. **整体看法**：134 项 CPU/结构测试通过；连击状态测试覆盖5秒边界、交替用户、tid去重、首尾相接、宽度固定和后续礼物推挤。演示和截图保留在本地 `演示视频/2026-11-11_13_连击数字/`，媒体未提交 Git。
6. **给 Claude 的建议**：请重点审查状态事件的半开区间语义和 `_freeze_gift_state_paths` 保留 reflow 的路径；少数方向重渲染仍按 CURRENT_TASK 排在本项之后。

机器：i7-14700KF / RTX 4070 Ti SUPER；实际用时约 50 分钟。gate 放行；`verify_all.py --tests-only` 通过。
