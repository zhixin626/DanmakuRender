# 10b4 实验：去掉 Encode 前 CPU 等待

1. **实验改动**：在 `perf/tmp/gpu_no_sync` 隔离 worktree 临时移除 `blend_ready.synchronize()`，未合并、未推送实验代码；正式分支保持安全 fence。
2. **同条件结果**：对同一 9105 帧素材用相同 500ms `nvidia-smi` 采样，保留等待 wall 40.7538s，去等待 wall 40.7736s，改善约 -0.05%，远低于 10% 采纳门槛。
3. **GPU 采样**：NVENC 20.62%→20.70%，NVDEC 11.47%→11.52%，GPU 5.41%→4.92%，显存峰值均 1637 MiB。采样工具的启动开销会拉长绝对时间，但两组相对比较一致。
4. **输出自检**：去等待版本返回码 0，1080×1920、50fps、9105 帧、182.100s；匹配 RenderPlan 前 1500 帧逐帧检查 0 candidate、0 flicker。
5. **结论**：不采纳 10b4。当前单路吞吐没有因去掉 CPU 等待而提升，且会放大竞态风险；正式代码继续保留阻塞 event fence。
