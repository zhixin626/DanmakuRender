# F：固定像素速度

1. **改了什么**：`DMR/Render/layout_compiler.py` 的 R2L 轨道新增 `r2l.speed`（像素/秒）；没有配置时按 `1920 / screen_duration` 兼容换算。轨道碰撞、路径终点和长短文字均使用同一速度；`DMR/Config/default.yml` 已写中文说明。新增 `tests/test_scroll_speed.py`，新增 `perf/night_speed.py` 和演示目录。
2. **为什么这样改**：横屏 1920 与竖屏 1080 若都按“8 秒过屏”，会产生 1.78 倍速度差；固定像素速度可以让主播横竖屏切换时滚动连续。
3. **遇到的问题和解决办法**：第一次演示检查使用默认 0.2 秒采样，只有 500/1500 帧；改为从 0 秒开始、50fps 全部 1500 帧后，两份输出均完整，候选闪烁 0、闪烁 0。
4. **意见和想法**：旧配置仍能工作；新配置可显式填写速度。F 的验证不依赖用户正式配置，也没有写入生产目录。
5. **整体看法**：123 项 CPU/结构测试通过；横竖屏 30 秒演示输出完成。媒体检查报告：`perf/tmp/night/speed/portrait_flicker.json`、`landscape_flicker.json`。
6. **给 Claude 的建议**：请重点审查旧 `screen_duration` 的兼容单位，以及 1080p 基准是否应在非 1080p 自定义画布上按比例换算；当前遵循 PLAN 的“以1080p画布为准”。

机器：i7-14700KF / RTX 4070 Ti SUPER，驱动 610.88，ffmpeg 2025-12-10-git-4f947880bd；实际用时约 24 分钟。

演示：`演示视频/2026-11-11_09_固定滚动速度/03_横竖屏原像素速度对比.mp4`，上方竖屏、下方横屏，观看文字每秒移动 240 像素；截图在 `perf/results/round_shots/09_*.png`。
